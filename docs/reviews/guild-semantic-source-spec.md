## Explicit consistency boundary

The IndexedDB read is a local transaction; hashing occurs afterward over its captured context. `assertCurrent()` is a **local point-in-time check immediately before an explicit remote request**, not a distributed transaction and not a guarantee that no other tab can edit local state after that read. An in-flight request remains the immutable consented payload. Server-side authorization, task revision, source identity, explicit-reconfirmation and idempotency checks remain authoritative (`supabase/migrations/202609060005_task_details.sql:38-71`). A privacy fence prevents stale UI continuations or follow-up dispatch after invalidation; it cannot cancel or undo a request already accepted remotely. Interrupted outcomes require explicit refresh/inspection and, where offered, an exact-payload retry, never hidden publication or automatic resend.
